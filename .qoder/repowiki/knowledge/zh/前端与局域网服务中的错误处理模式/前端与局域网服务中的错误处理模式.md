## 1. 整体方法
仓库没有统一的自定义异常类或全局错误中间件，而是采用**“局部 try/catch + console.warn/console.error + 用户可见 toast”**的组合方式：
- 浏览器端通过 `try/catch` 包裹 I/O、解码、网络调用等易失败操作；
- 对可恢复的失败（如 PSD 预览生成、云端同步、局域网分发）记录 `console.warn`/`console.error` 并通过 `toast(message, 'error')` 向用户反馈；
- 对不可恢复的校验失败直接 `throw new Error(...)`，由上层调用方捕获；
- 局域网 Node.js 服务端使用 `catch (error) { if (error?.code !== 'ENOENT') ... }` 区分“文件不存在”和真正异常，并以 `console.warn`/`console.error` 输出。

## 2. 关键位置
- **前端 UI 通知**：`src/store/uiStore.ts` 定义 `ToastKind = 'info' | 'error' | 'success'`、`pushToast`、`removeToast`，并导出便捷函数 `toast(message, kind)`；`src/components/Toasts.tsx` 渲染到页面底部。所有用户可见的错误提示都走这个通道。
- **文件导入/上传**：`src/io/fileLoader.ts` 是错误处理最集中的地方：视频缩略图抓取失败返回空、PSD 预览失败 `console.warn` + `toast('...无法生成预览', 'error')`、超过 1.5GB 的文件跳过并 toast、`importFiles` 中每个文件单独 try/catch 后 toast 失败信息、`updateAssetText` 找不到素材时 `throw new Error('素材不存在')`。
- **云端同步**：`src/sync/cloudSync.ts` 所有 Supabase 调用在检测到 `error` 字段时仅 `console.warn('...失败:', error.message)` 并返回默认值（空数组 / null / false），不向上抛出，使调用方可继续降级运行。
- **局域网服务器**：`server/lan-server.mjs` 大量使用 `try/catch` 保护文件读写、JSON 解析、备份清理等；对 ENOENT 明确忽略，其他异常用 `[SuQCanvas LAN] Failed to ...` 前缀的 `console.warn`/`console.error` 输出；HTTP 流式读取出错时若响应头未发送则写 500，否则销毁连接；资产分片写入失败会关闭句柄、删除临时文件并从 pending 状态移除。
- **剪贴板/画布辅助**：`src/canvas/clipboard.ts` 在缺少素材引用、PSD 预览失败、图片解码失败、无法创建画布、编码失败等场景 `throw new Error(...)`，属于“参数/环境不合法”的强约束错误。

## 3. 架构约定
- **无全局错误边界**：React 应用没有挂载全局 `componentDidCatch` 或 `window.onerror` 处理器，错误传播依赖各模块自行 try/catch。
- **降级优先于中断**：非关键路径（预览生成、云端同步、局域网分发、备份清理）一律 catch 后降级，保证主流程（导入文件、保存项目）不因旁路失败而中断。
- **用户可见错误必须走 toast**：所有影响用户操作的失败都会调用 `toast(..., 'error')`，且消息模板统一为 `「${file.name}」...失败` 的形式，便于定位具体文件。
- **服务端以 ENOENT 作为“正常缺失”信号**：加载 projects.json、orphan marks、备份目录扫描等启动期/维护期逻辑均显式判断 `error?.code !== 'ENOENT'` 才告警，体现“数据文件不存在不算错误”的约定。
- **WebSocket 错误静默关闭**：`wss.on('error', () => ws.close())` 不抛错，避免单个客户端异常拖垮整个服务器。

## 4. 约束与规则
- 所有 toast 的 `kind` 仅限 `'info' | 'error' | 'success'`（`uiStore.ts` 类型约束）。
- 云端同步函数在 Supabase 返回 `error` 时**不 throw**，而是 `console.warn` 并返回默认值，调用方不得假定其成功。
- 局域网服务器对 `readFile`/`readdir`/`access` 等文件系统调用统一使用 `try/catch`，仅 ENOENT 视为正常分支，其余一律记录警告日志。
- 大文件（>1.5GB）在导入阶段被主动拒绝并 toast，不会进入后续 I/O 流程。
- 资产 ID 必须通过 `isSafeId` 正则校验（`server/lan-server.mjs`），非法 ID 的消息会被直接丢弃，防止路径穿越或注入。
- 项目删除需校验 `creatorId`，非创建者删除会返回 `{ t: 'project-delete-denied', projectId }`，体现服务端权限校验而非前端信任。
- 备份恢复请求同样校验 `creatorId`，过期备份（>24h）返回 `expired` 并清理文件。
